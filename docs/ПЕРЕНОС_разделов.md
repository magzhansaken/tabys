# Шпаргалка переноса: 21 раздел в дизайн-системе «Табыс»

Одна страница. По строчке на случай. Всё берётся из `admin/lib/ui.tsx` —
новых компонентов заводить не нужно.

---

## Шапка раздела — одинаковая всюду

```tsx
<div style={{ display: 'flex', justifyContent: 'space-between', alignItems: 'flex-end',
              gap: 20, flexWrap: 'wrap', marginBottom: 20 }}>
  <div>
    <h1 style={{ fontSize: 27, fontWeight: 600, letterSpacing: '-.015em', margin: 0 }}>Товары</h1>
    <div style={{ fontSize: 13.5, color: C.dim, marginTop: 5 }}>348 позиций · 11 категорий</div>
  </div>
  <div style={{ display: 'flex', gap: 8, flexWrap: 'wrap' }}>
    <Btn kind="ghost">Скачать Excel</Btn>
    <Btn>Новый товар</Btn>
  </div>
</div>
```

Подзаголовок — факт о разделе (сколько чего), а не описание раздела.
Главное действие одно и всегда справа, `kind="primary"`.

## По случаям

**Показатели и цифры.** `Stat` в `display: grid` +
`gridTemplateColumns: 'repeat(auto-fit, minmax(212px, 1fr))'`, `gap: 14`.
Главная сумма раздела — не `Stat`, а своя строка 46 px / 600 в `Card`:
на экране крупная цифра ровно одна. Проценты роста — 13,5 px, `C.accent`
на рост, `C.red` на падение. Спарклайн — `<svg width="70" height="22">`,
`polyline`, `strokeWidth 1.6`, без осей и подписей.

**Таблица списка.** `DataTable` всегда, `Table` — только внутри карточки на
5–6 строк без поиска. `hint` — одна строка: зачем раздел и с чего начать
(«Черновик не меняет остатки — на учёт влияет только проведение»), не
описание столбцов. `storageKey` — короткое имя раздела (`'goods'`,
`'stock-docs'`). `exportName` — то же имя: выгрузка отдаёт то, что видно.
`extra` — фильтры раздела (склад, категория, тип документа), 1–3 контрола,
не больше; всё прочее живёт во вкладках.

**Документ с позициями.** Шапка документа — `Card` с номером, `Status` и
контрагентом в заголовке, итог и «Провести» в правом нижнем углу шапки.
Строки — `Table` без поиска внутри той же карточки. Форма добавления строки
— над таблицей, в одну линию `flex` + `gap: 12`, `alignItems: flex-end`.
Итог по документу — 19 px / 600, рядом с кнопкой проведения, чтобы человек
видел сумму в момент решения.

**Форма создания.** `Field` + `Input` в `flex` + `gap: 14`,
`flexWrap: 'wrap'`, `alignItems: 'flex-end'` — одна строка на компьютере,
столбик на телефоне. Ширину поля задавайте по содержимому: название 268,
цена 110, количество 96. Ни одной формы в два столбца: на 390 px второй
столбец всё равно уедет вниз, а порядок полей станет непонятным.

**Вкладки внутри раздела.** `Tabs` сразу под шапкой, до первой карточки.
До 7 вкладок — как в отчётах. Больше — значит, это два раздела.

**Опасное действие.** `Btn kind="danger"` — контур `#E6C7C0`, текст
`C.red`, заливки нет: красная кнопка не должна быть самой заметной на
экране. Всегда `confirm()` с последствием в тексте («Движения по складу
будут отменены»), а не «Вы уверены?». Проведённый документ не удаляют —
сторно.

**Сигналы.** Расхождение по смене, долг, возврат — `C.red`, `fontWeight
600`, знак «−» настоящий. Доля скидки от 15% — `C.red`; ниже — обычный
текст. «Закончился совсем» — `Badge tone="bad"`, «мало осталось» —
`Badge tone="warn"`: это разные вещи, в первом случае продажи уже
потеряны. Больше трёх красных пятен на экране — экран перестаёт
предупреждать.

**Пустое состояние.** `DataTable` рисует его сам; текст задаёте вы —
`empty="Остатков нет — проведите первую приёмку"`. Структура: чего нет +
что нажать. Не «Нет данных», не «Список пуст».

## Три вещи, которые легко сломать

1. `Select` принимает `options=[{value,label}]`. Вложенные `<option>`
   роняют сборку — так уже было.
2. Выбор столбцов читается только внутри `useEffect`. Вынесете наверх —
   страница упадёт при сборке.
3. Перевод статусов один, в `Status`. Свой бейдж в разделе — это второй
   перевод; из-за него проведённый документ однажды показывался служебным
   английским словом.

## Телефон

Ничего не делаете: карточки из таблиц и печать приходят из `BaseStyles`.
Ваша часть — не ставить `width` меньше 44 px на нажимаемое и не писать
`fontSize` меньше 16 у полей ввода.
