# Опись возможностей: донор и «Табыс»

Сделана в восьмом заходе сверки. Смотрит не разметку и не поведение, а
**что вообще умеет каждая система**.

## Адреса

| | |
|---|---|
| У донора | 21 |
| У меня | 18 + свои |
| Пропущено у меня | **ничего** |

Расхождения оказались в именах, не в возможностях:

| Донор | У меня | Почему так |
|---|---|---|
| `tenant-card` | `/clients/:id/card` | клиент, а не «арендатор» |
| `leads` | `signups` | заявки с сайта попадают в общий список клиентов |
| `tenant/update` | `/clients/:id` | одно название для одной вещи |

## Слова

Все восемь «пропавших» действий нашлись под понятными названиями:

| Донор | У меня |
|---|---|
| Заведение | **Магазин** |
| Платежи | **Деньги** |
| Состав тарифа | **Состав счёта** |
| Сбросить пароль владельца | **Новый пароль владельцу** |
| Учебное заведение | **Учебный магазин** |
| Отправить запрос | **Запросить у платформы** |
| История | **Оплаты** |
| Почему отказ | **Причина отказа** |

Правило простое: человек в магазине не говорит «заведение» и
«платежи». Он говорит «магазин» и «деньги».

## Чего у донора нет вовсе

| Возможность | Зачем |
|---|---|
| **Кнопка «Выйти»** | у донора её нет — с общего компьютера не выйти |
| **Код для кассы** | без него магазин заведён, а продавать нельзя |
| **Добавить устройство** | владелец даёт кассу сам, без заявки от партнёра |
| **Снова по фактам** | вернуть карточку воронки из ручного этапа |
| **Правка имени и почты партнёра** | на месте, без отдельного окна |
| **Итог дня партнёру** | иначе он не узнает, что доля начислена |
| **Три периода в сводке** | у донора жёстко 30 дней |
| **Вкладки веса в журнале** | у донора только галочка «деньги» |
| **Отбор клиентов по состоянию** | семь вкладок вместо одного списка |

## Чего нет у меня — и почему

Ничего. Все возможности донора перенесены.

Единственное устройство, сделанное **иначе**: заявки с сайта. У донора
это отдельный раздел, у меня — вкладка «Ждут подтверждения» в общем
списке клиентов. Один список вместо двух: не надо помнить, где искать.
