# ЧАСТЬ 18 — КОНСУЛЬТАНТЫ, ЧЕК ПОКУПАТЕЛЯ И ПРИЁМКА «ДЕНЬ МАГАЗИНА»

Прочитано перед работой: **UMAG** «Консультанты» (справочник ID/имя/телефон;
привязка к продаже «чтобы вести учёт продаж консультантов и составления
статистики» — процента и расчёта выплат нет); **Wipon** «Брендирование чека»
(логотип PNG/JPG до 500 КБ + рекламный текст), Cashback печатает начисление
на чеке, free-версия — «бонусы от 1000 ₸»; **МойСклад** — десяток вариаций
товарного чека (со скидкой по каждой позиции, с артикулом и т.д.).

---

## 1. Консультанты: у UMAG статистика — у нас зарплата

| | UMAG | Мы |
|---|---|---|
| Справочник | ID, имя, телефон | то же + **процент с продаж (0–50%)** |
| В чеке | привязка к продаже | выбор на кассе в один тап, работает офлайн |
| Расчёт выплат | вручную в Excel | отчёт «К выплате» = (выручка − возвраты по его чекам) × % |
| Возвраты | — | вычитаются из базы комиссии: продал и приняли обратно — процента нет |

Реализация: миграция 025 (`commission_percent` + SQL-функция
`consultant_report`, где возврат находит консультанта через исходный чек);
CRUD `/admin/consultants`; вкладка «Консультанты» в отчётах кабинета; блок
«Продавцы-консультанты» на странице сотрудников; список консультантов в
bootstrap кассы → кнопка «Продавец» в чеке.

Приёмочный тест закрепляет формулу: Ерлан продал 800, вернули 400 →
к выплате (800−400)×10% = **40 ₸**.

## 2. Чек покупателя

После способов оплаты чек печатает (ESC/POS, работает офлайн):
- `Бонусами: N` — как способ оплаты;
- `Начислено бонусов: +X` — модель Wipon Cashback (клиент должен видеть выгоду);
- `Бонусный баланс: Y` — сколько накоплено;
- **`ВАШ ДОЛГ: Z тг`** жирным — наша строка: «тетрадь» прозрачна и для
  покупателя, спорам «я столько не должен» нечем питаться;
- `Вас обслуживал(а): Имя` — консультант.

Контекст строк собирает `completeSale` до очистки корзины
(`bonusEarned/bonusBalanceAfter/debtAfter/consultantName`).

## 3. ★ Приёмочный тест «День магазина» (part18.acceptance)

Один тест проживает путь владельца целиком: регистрация с автотриалом →
импорт номенклатуры из Excel (авто-сопоставление колонок) → приёмка →
кассир+продавец+касса+покупатель с лимитом → **офлайн торговый день**:
наличные со скидкой и округлением вниз, карта с консультантом, смешанная,
долг, оплата бонусами, отмена позиции, внесение/изъятие, погашение долга,
возврат → закрытие с недостачей и комментарием → вечер владельца: дашборд,
валовая прибыль, P&L, смены, кассиры, консультанты, долговая книга, бонусы,
склад по каждому товару — **всё до тенге**, повтор очереди ничего не задваивает.

Правило команды: этот тест — ворота релиза. Красный — на пилот не едем.

## 4. Найдено и починено проверкой

1. **Две конвенции знака возврата** (онлайн `+`, офлайн `−`) дотянулись до
   дашборда: выручка завышалась на сумму возврата. Системный фикс: сервер
   **нормализует офлайн-возврат при записи** (суммы по модулю, «возвратность»
   несёт `return_of_id`, склад двигается в плюс движением `sale_return`) —
   вместо россыпи `abs()` по каждому отчёту, где однажды кто-то забыл бы.
2. **Ловушка «to=сегодня»**: дата без времени означала полночь *начала* дня —
   P&L и ДДС «за сегодня» из кабинета были пустыми. Теперь дата в «по»
   означает конец дня (`dayEnd()` в одном месте роутера).
3. Ожидание бонусов в тесте исправлено на честное: порог программы по
   умолчанию 1000 ₸ — модель Wipon «бонусы от 1000», чек 430 начисления
   не даёт, и это правильно.
