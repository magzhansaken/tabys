## 1. Канал перетока доказан конкурентом

У Wipon в документации есть тег **«для клиентов Umag»**. Под ним ровно одна
страница — «Обзор раздела Товары».

Это важнее, чем кажется. Wipon **застолбил канал, но не наполнил его**: тег
есть, а инструкции по переезду с UMAG нет. Значит переток клиентов от UMAG
реален настолько, что конкурент завёл под него отдельную метку — но забирать
их системно он не умеет.

**Наш ход:** сделать переезд не статьёй, а кнопкой.

## 2. Что мы знаем про формат выгрузок

Wipon, «Импорт номенклатуры»:
> Типы импорта: **С остатками** / **Без остатков**.
> Обязательные поля (с остатками): Наименование, Единица измерения, Цена
> продажи, Штрихкод, Количество, Цена закупки.
> Без остатков: Наименование, Единица измерения, Цена продажи, Штрихкод.
> После начинается **процесс определения столбцов таблицы** под подходящие
> параметры… Проверьте, не является ли верхний ряд файла названиями столбцов.
> Если да — отметьте галочкой поле **Заголовок**.

Это ровно та модель, которую надо взять: Excel → сопоставление столбцов →
импорт. Но у неё есть слабое место — **сопоставлять столбцы вручную должен
человек**. Владелец магазина, который первый раз видит слово «номенклатура»,
не понимает, какой столбец класть в «Артикул».

**Наше решение:** колонки распознаются сами. Заголовки выгрузок UMAG и Wipon
известны заранее — программа их узнаёт и предлагает готовое сопоставление,
человек только подтверждает. Ручное сопоставление остаётся как запасной путь
для произвольного файла.

**Честно:** живого кабинета UMAG у меня нет — купить подписку 8800 ₸ и снять
реальные выгрузки остаётся в открытых вопросах с Части 1. Поэтому распознавание
построено на **заголовках, которые видны в их же документации** (список
колонок «Списка товаров», «Покупателей», «Поставщиков»), и устроено так, что
незнакомый заголовок не ломает импорт, а попадает в ручное сопоставление.

## 3. Решения

### 3.1 Импорт понимает любую из трёх выгрузок
Один движок, три словаря заголовков (UMAG, Wipon, МойСклад) плюс общий
русско-казахский. Формат определяется по совпадению колонок, а не по имени
файла.

### 3.2 Дубли ловим до записи, а не после
Переезд — это единственный момент, когда в базу заливают тысячи строк разом.
Если в выгрузке два «Молока» с одним штрихкодом, магазин получит вечную
путаницу в остатках.

Проверяем: повтор штрихкода, повтор артикула, повтор названия, штрихкод уже
в базе. Показываем **до** импорта.

### 3.3 Переносим не только товары
Wipon импортирует номенклатуру. Но у магазина, который переезжает, есть ещё
**долги покупателей** и **поставщики** — то, ради чего он и вёл тетрадку.
Их перенос — часть переезда: контрагенты, остатки, долги (через `balance_move`
из Части 6), цены.

### 3.4 Мастер первого запуска: «магазин за час»
Шаги, каждый — одно решение, все пропускаемые:
организация → точка и склад → сотрудники → импорт или ручной ввод →
фискализация → оборудование → первая продажа.

Мастер помнит, где остановились, и показывает готовность в процентах.
Ничего не блокирует: магазин может начать торговать после третьего шага.

### 3.5 Казахская локализация — из зеркала Wipon
У них есть полное казахское зеркало документации. Из него собран словарь
терминов — это живая терминология, на которой уже работают казахстанские
магазины, а не машинный перевод:

| Русский | Казахский (Wipon) |
|---|---|
| Номенклатура | Номенклатура |
| Остатки товаров | Тауар қалдықтары |
| Цена закупки / продажи | Сатып алу бағасы / Сату бағасы |
| С остатками / Без остатков | Қалдықтарымен / Қалдықтарсыз |
| Долговая книга | Қарыз кітабы |
| Контрагенты / Поставщики | Контрагенттер / Жабдықтаушылар |
| **ЭСФ / СНТ / АВР** | **ЭШФ / ТІЖ / ОЖА** |
| Доверенности | Сенімхаттар |
| Акты сверки | Салыстырып тексеру актілері |
| Оприходование | Кіріске алу |
| НДС | ҚҚС |
| Заголовок (в импорте) | Тақырып |

Особенно ценны сокращения документов: **ЭСФ → ЭШФ**, **СНТ → ТІЖ**,
**АВР → ОЖА**. Их не угадать переводом — это официальные казахские аббревиатуры.

## 4. Что сознательно НЕ делаем

- **Прямая выкачка из кабинета UMAG** (парсер их личного кабинета) — это
  чужая система и юридически мутно. Работаем с файлами, которые владелец
  выгрузил сам: это его данные.
- **Полный перенос истории продаж** — переносим справочники, остатки и долги.
  История чеков остаётся в старой системе: тянуть её незачем, а рисков много.

## 7. Что нашла проверка

1. **★ Мастер отдавал состояние из незакоммиченной транзакции.** `completeStep`
   вызывал чтение состояния внутри `withTenant` — вложенный вызов берёт из пула
   другое соединение и не видит только что вставленную строку. Тот же класс
   ошибки ловили в Части 6. Чтение вынесено за коммит.
2. **★ Отметка «готово» не должна ничего значить сама по себе.** Тест показал:
   владелец нажал «готово» на шаге реквизитов, не заведя организацию — шаг
   остался открытым, потому что состояние считается по фактам в базе. Это
   правильно и теперь зафиксировано проверкой: галочка без дела не считается.
3. Вызов переноса долга не совпадал с сигнатурой функции из Части 6 —
   в поле способа оплаты уезжал идентификатор сотрудника.
