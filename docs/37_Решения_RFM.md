# Часть 37 — RFM-анализ клиентов

## Что разобрано (методика RFM, веб-поиск 2026)

- **RFM** = Recency (давность последней покупки), Frequency (число покупок за
  период), Monetary (сумма/средний чек). Каждый параметр → балл; итог —
  трёхзначный код (555 = чемпион, 111 = потерян).
- Для **розницы**: R = дни с последней покупки, F = число чеков, M = сумма.
  Пороги подбираются под бизнес.
- **Сегменты**: чемпионы (высокие R/F/M), лояльные, под угрозой оттока (низкий
  R, высокие F/M), новички, потерянные. Используют Amazon, Netflix и тысячи
  ритейлеров.
- Цель — не «вклад клиента» (это у нас с части 31), а **сегментация для
  действий**: кому скидку, кого реактивировать.

## Наши решения и почему

### 1. Баллы 1-3 (проще, чем 1-5)
Для магазина у дома трёхзначная шкала 1-5 избыточна. Берём 1-3: понятнее и
устойчивее на малой базе. R: ≤14 дн=3, ≤45=2, иначе=1; F: ≥5=3, ≥2=2, иначе=1;
M: треть/треть/треть по сумме (ntile).

### 2. Человеческие сегменты с рекомендациями
Не сухой код «313», а название + действие: Чемпионы («поощряйте — эксклюзивы»),
Лояльные, Под угрозой оттока («срочно вернуть — скидка»), Засыпающие
(«реактивация»), Новички («welcome-бонус»), Потерянные, Обычные. Проверено:
чемпион, засыпающий (R=1 при 60 днях), новичок классифицированы верно.

### 3. Пороги настраиваются
R/F-пороги передаются параметрами — бизнес подстроит под свою частоту покупок
(продуктовый магазин vs магазин техники). Дефолт — период 180 дней.

### 4. Связь с рассылками
Выборка клиентов сегмента (`/rfm/segment`) — готовый список для рассылки или
персональной скидки. Соединяется с сегментами лояльности (часть 19).

### 5. НЕ делаем ML-прогноз оттока/CLV
Осознанно из плана. Прогнозные модели (Churn, CLV) избыточны для магазина у
дома — важна понятная сегментация, которую владелец сам применит.

## Что сделано
- Миграция `043_rfm.sql`: функция `rfm_analysis` (R/F/M-баллы по клиентам за период, пороги параметрами)
- `server/src/rfm/rfm.module.ts`: `classify` (сегмент+рекомендация), анализ со сводкой, выборка сегмента
- Эндпоинты: `GET /rfm` (анализ+сводка), `GET /rfm/segment?segment=X` (для рассылки)
- Кабинет: страница «RFM-анализ» — карточки-сегменты (кликабельные), таблица клиентов с R/F/M

## Границы (честно)
- RFM считается по клиентам с указанным `customer_id` в продаже — анонимные
  чеки в анализ не попадают (это верно: без клиента нет сегментации).
- Сезонность не учитывается (магазин ёлочных игрушек в январе покажет «отток»)
  — для магазина у дома некритично; при желании период задаётся вручную.
