# Часть 28 — Мобильный кабинет владельца (PWA)

## Что разобрано у конкурентов

| Кто | Мобильное приложение |
|---|---|
| **Wipon** | Wipon Mobile — 30 разделов. Аналитика в реальном времени: доход, число чеков, средний чек, топ-товары. «Принимайте управленческие решения прямо с телефона». |
| **МойСклад** | Приложение = веб-версия + ТСД + задачи + мессенджер. «Владелец бизнеса — следите, какие точки открылись». |
| **UMAG** | Мобильный доступ к показателям. |

У всех троих — нативное приложение из сторов. У нас был только десктоп-кабинет
и касса (Flutter).

## Наши решения и почему

### 1. PWA, а не нативное приложение
Ключевое решение. Для дашборда владельца нативное приложение — избыточно.
PWA (Progressive Web App):
- **устанавливается «на экран» одним тапом** — без App Store и Google Play;
- **обновляется мгновенно** — не нужно ждать ревью в сторах (2-7 дней);
- **один код для iOS и Android** — не две команды разработки;
- работает офлайн (service worker кэширует оболочку).

Для «посмотреть выручку и открытые точки с телефона» этого более чем
достаточно. Нативное приложение имело бы смысл для кассы (там нужен принтер,
сканер, работа без сети) — и касса у нас как раз нативная (Flutter). А кабинет
владельца — PWA. Каждому инструменту своя технология.

### 2. Живой снимок вместо тяжёлого дашборда
Один компактный эндпоинт `/reports/mobile/snapshot`: сводка за сегодня
(выручка, прибыль, чеки, средний чек, возвраты) + **открытые смены по точкам**
(кто на кассе прямо сейчас, сколько наторговал). Не тянем весь десктопный
дашборд — телефону нужно быстро и по делу.

Модель МоегоСклада «какие точки открылись» + аналитика Wipon в реальном
времени, сведённые в один экран. Обновление автоматическое каждые 30 секунд.

Проверено: 3 продажи по 200 → снимок показывает выручку 600, прибыль 240,
1 открытую точку с названием кассы и кассира.

### 3. Переиспользуем готовую аналитику
Сводка берётся из существующего `dashboardDay` (часть 3) — не считаем заново.
Открытые смены — из таблицы `shift` с фильтром `closed_at IS NULL`. Ничего
не дублируем.

## Что сделано
- `server/src/reports/report.service.ts`: метод `mobileSnapshot` (сводка дня + открытые смены)
- Эндпоинт `/reports/mobile/snapshot`
- `admin/public/manifest.webmanifest`, `sw.js`, иконки 192/512 — PWA-оболочка
- `admin/app/m/page.tsx` — мобильный дашборд (вход, сводка карточками, открытые точки, автообновление)
- `admin/app/layout.tsx` — PWA-мета (manifest, theme-color, apple-web-app, viewport)

## Границы (честно)
- Push-уведомления на телефон (браузерные) — задел на будущее: PWA их
  поддерживает, но настройка VAPID-ключей и разрешений — отдельная тема.
- Офлайн показывает последнюю закэшированную оболочку; свежие данные —
  по сети. Полноценной офлайн-аналитики нет (и не нужна для дашборда).
- Действия с телефона (продать, оформить возврат) — не добавляли: касса для
  этого есть отдельно. Мобильный кабинет — про наблюдение, а не про кассовые
  операции.
