# Часть 32 — Интеграция с маркетплейсом (Kaspi Магазин)

## Что разобрано (реальный протокол Kaspi Shop API v2, веб-поиск 2026)

- **Формат JSON:API.** Заголовки: `X-Auth-Token`, `Content-Type: application/vnd.api+json`.
- **Заказы:** `GET /shop/api/v2/orders?filter[orders][state]=NEW&filter[orders][status]=APPROVED_BY_BANK`, пагинация `page[number]/page[size]`.
- **state (этап):** NEW → SIGN_REQUIRED → PICKUP/DELIVERY/KASPI_DELIVERY → ARCHIVE.
- **status:** APPROVED_BY_BANK → ACCEPTED_BY_MERCHANT (принять) → COMPLETED/CANCELLED.
- **Принять заказ:** `POST /shop/api/v2/orders {data:{type:orders,attributes:{code,status:ACCEPTED_BY_MERCHANT}}}`.
- **Позиции:** `GET /shop/api/v2/orders/{id}/entries` — code, name, basePrice, quantity.
- **deliveryMode:** DELIVERY_PICKUP (самовывоз) / DELIVERY_REGIONAL_TODOOR (доставка).
- **Выгрузка товаров:** прайс (цена+остаток), **не выгружать то, чего нет** в наличии.
- **>90% онлайн-торговли КЗ идёт через Kaspi** — это канал №1.

## Что разобрано у конкурентов

| Кто | Маркетплейсы |
|---|---|
| **МойСклад** | Интеграция с Kaspi (заказы, товары, остатки, цены), авто-приёмка, FBO/FBS, + Ozon/WB/ЯМаркет. Грабли: «нераспознанные позиции» без маппинга по коду. |
| **Wipon** | Интеграции с маркетплейсами нет. |
| **UMAG** | Нет. |

Это направление, где мы обходим Wipon и UMAG сразу, а МойСклад — по КЗ-специфике.

## Наши решения и почему

### 1. Kaspi первым — это канал №1 в Казахстане
Не Ozon и не WB (у них доля в КЗ мала), а именно Kaspi Магазин — через него
идёт большинство онлайн-покупок. Провайдерный паттерн (как fiscal/payment):
интерфейс + Mock + Kaspi, задел на Ozon/WB.

### 2. Два потока: выгрузка и заказы
- **Выгрузка**: наш каталог → цены и остатки на Kaspi. Только то, что есть в
  наличии (правило Kaspi — отсутствующие не обрабатываются).
- **Заказы**: Kaspi → наши заказы. Принять → собрать → выдать.

### 3. Единый остаток — защита от двойных продаж
Главная боль продавца на маркетплейсе: продал в рознице то, что уже заказали
на Kaspi. У нас **один остаток**: завершение заказа Kaspi списывает тот же
склад, что и касса. Проверено: заказ на наушники → остаток упал с 20 до 19.

### 4. Явный маппинг product ↔ SKU
МойСклад страдает «нераспознанными позициями», когда товар не связан по коду.
Мы делаем маппинг обязательным и **не даём отгрузить незамапленную позицию** —
иначе остаток поедет неверно. Проверено: заказ с неизвестным SKU нельзя
завершить.

### 5. Идемпотентность заказов
Повторный запрос заказов (провайдеры дублируют) не задваивает — по external_id.
Проверено: второй pull → saved=0.

### 6. Авто-приём (опционально)
Флаг `auto_accept`: новые заказы принимаются автоматически при заборе, чтобы
не терять время (Kaspi штрафует за просрочку принятия).

## Границы (честно)
- Боевой `X-Auth-Token` выдаётся по договору мерчанта Kaspi — механика запросов
  готова по реальному протоколу v2, включается подстановкой токена.
- Выгрузка прайса на Kaspi идёт отдельным price feed (XML/список по договору) —
  форма готова, боевая выгрузка по регистрации.
- FBS (товар у продавца) реализован; FBO (товар на складе Kaspi) — задел.
- Kaspi Доставка (накладная, курьер) — следующий шаг, если понадобится.
