Дата: 16.07.2026. Прочитано перед решением:

- **UMAG**: разметка платформ по всем 40 статьям (блоки «## Платформа: …»),

- **Wipon**: intro всех четырёх продуктов (web, desktop, mobile, forte-sunmi),

## 1. Сколько приложений держат конкуренты

| | Кабинет | Касса на ПК | Касса мобильная | POS-терминал | Итого кодовых баз |
|---|---|---|---|---|---|
| **UMAG** | Web (38 статей) | **нет** | iOS (20) + Android (20) | — | 3 |
| **Wipon** | Web | **Wipon Desktop** (Windows) | Wipon Mobile | **Wipon Forte Sunmi — отдельное приложение** | 4 |
| **МойСклад** | Web | Windows, MacOS, Linux | Android, iOS | — | 4+ |

### Что из этого следует

**У UMAG нет кассы для Windows.** В документации слово Windows не встречается
ни разу: касса — это Android или iOS. Для магазина у дома, где стоит старый
системный блок с монитором и денежным ящиком, это означает «купите планшет».

**Wipon держит четыре кодовые базы** — и отдельное приложение под терминал
Forte Sunmi, хотя Sunmi это обычный Android. Каждая новая функция пишется
четыре раза.

**У МоегоСклада платформы разъехались.** В их собственной таблице сравнения
видно: разрешительный режим маркировки офлайн — Windows ✅, Android ✅,
MacOS ❌, Linux ❌. Сенсорный экран — только Windows и Android. Клиент на
Linux живёт с урезанной кассой и узнаёт об этом из таблицы.

**Наш вывод.** Одна кодовая база на Flutter даёт Windows, Android, iOS, Linux,
macOS — и Sunmi бесплатно (это Android). Мы не экономим на команде ради
экономии: мы покупаем этим **отсутствие расхождений между платформами**.
Функция выходит везде одновременно, и у нас физически не может появиться
таблица «а на Linux вот это не работает».

## 2. Три приложения — и почему именно так

### 2.1 Касса (Flutter): Windows + Android + iOS одним кодом

Ставка на Windows принципиальна. В магазинах у дома в Казахстане чаще всего
уже стоит ПК: к нему подключены сканер, чековый принтер, денежный ящик, весы.
UMAG предлагает им уехать на планшет. Мы приходим на то железо, которое есть.

Android нужен для Sunmi и планшетов (Wipon делает под Sunmi отдельное
приложение — мы просто ставим то же самое). iOS — по остаточному принципу,
но бесплатно.

### 2.2 Кабинет (Next.js): веб, как у всех троих

Здесь спорить не с чем: у всех троих кабинет — веб, и это правильно. Владелец
смотрит выручку с телефона в такси и с ноутбука дома.

### 2.3 Сервер (NestJS): уже написан в 1.2–1.3

В 1.4 добавляем то, без чего каркас не каркас: проверка живости, версия сборки,
единый конфиг, структура монорепо.

## 3. Ключевые решения по кассе

### 3.1 Локальная база — источник правды для кассира

Касса читает и пишет **только свою SQLite**. Сеть — это фоновый процесс обмена,
а не условие работы. Продажа не ждёт сервер никогда.

### 3.2 Офлайн-вход (то, ради чего затевалась 1.2)

При привязке устройство получает пакет: сотрудники с хэшами PIN, их роли и
разрешения кассы. Всё это ложится в локальную базу. Дальше вход по PIN —
локальная проверка хэша, без единого запроса к серверу.

Проверка этого — критерий готовности всей Части 1: **гасим сервер и логинимся**.

### 3.3 Очередь событий переживает всё

Прямая ошибка Wipon (их же документация): *«локальные продажи, не переданные
на сервер, могут быть потеряны при удалении папки `wipon-desktop`»*.
У нас очередь лежит в той же базе, что и продажи, в защищённом каталоге
приложения; при удалении — предупреждение с числом непереданных продаж.

### 3.4 Хранение секретов

Токен устройства — не в текстовом файле рядом с программой, а в хранилище ОС
(Windows Credential Manager, Android Keystore, iOS Keychain). Украли системный
блок — токен из него не вынуть, а владелец отвяжет кассу из кабинета.

## 4. Структура монорепозитория

```
shop/
  db/migrations/     — SQL-миграции (001 ядро, 002 аутентификация, 003 синхронизация)
  server/            — NestJS: API, WebSocket
  pos/               — Flutter: касса (Windows, Android, iOS)
  admin/             — Next.js: кабинет владельца
  docs/              — решения по каждой подчасти
  shared/            — общие константы и типы (разделы прав, коды ошибок)
```

Монорепо, а не три репозитория: протокол синхронизации и список прав должны
меняться в одном коммите на всех трёх сторонах, иначе кабинет и касса разъедутся.

---

## 5. Что сознательно НЕ делаем

- **Отдельное приложение под Sunmi** (как Wipon) — это Android, ставим то же.
- **Разные функции на разных платформах** (как у МоегоСклада) — либо функция
  есть везде, либо её нет.
- **Веб-кассу** — браузер не даёт нормальной работы со сканером, ящиком и
  печатью, а офлайн в браузере хрупкий.
- **Electron для кассы** — 150 МБ и полгигабайта памяти на старом ПК магазина.

---

## 6. Честное ограничение проверки

Flutter SDK в песочнице поставить нельзя: домены Google для загрузки закрыты,
пакета Dart в системе нет. Поэтому:

- код кассы (схема локальной базы, офлайн-аутентификация, очередь) написан,
  но **собирается на машине разработчика**, командой из README;
- **алгоритм и схема проверены по-настоящему**: то же самое воспроизведено на
  реальной SQLite, с реальными bcrypt-хэшами из сервера, и проверено при
  выключенном сервере;
- сервер и кабинет собираются и проверяются здесь полностью.

Это ограничение песочницы, а не продукта, и оно указано прямо, чтобы не
выдавать ненаписанное за готовое.

## 8. ПРОВЕРКА

### Критерий готовности Части 1 — 29 из 29
`server/test/part1.criteria.js`. Сценарий целиком, с реальным выключением сервера:
создание компании и точки → кассир с PIN → привязка кассы одноразовым ключом →
пакет для офлайна в локальную SQLite → **сервер убит** → вход кассира по PIN
без сети → проверка прав офлайн → переключение на владельца → подтверждение
возврата PIN владельца офлайн → события копятся в очереди → блокировка перебора
офлайн → сеть вернулась → очередь улетела, дублей нет, сервер подтверждает
полноту данных.

### Каркасы — 10 из 10
`server/test/part1.frame.js`: сервер и база живы, версия отдаётся, кабинет
собран и отдаёт страницы, протухший access-токен обновляется прозрачно —
владельца не выкидывает из кабинета посреди работы.

### Что осталось непроверенным (честно)
Flutter-код кассы (`pos/`) написан, но собирается на машине разработчика:
в песочнице нет Flutter SDK и его нельзя загрузить. Проверены **схема
локальной базы и алгоритм офлайн-входа** — воспроизведены на реальной SQLite
с настоящими bcrypt-хэшами, приехавшими с сервера. Команда сборки — в README.
