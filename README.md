## Запуск на ноутбуке одной командой

Нужны Node.js 20+ (nodejs.org) и PostgreSQL 16+ (запущенный).

- **Windows**: двойной клик по `start.bat`
- **Linux/macOS**: `./start.sh`

Скрипт создаст базу, соберёт сервер и кабинет, поднимет API (:3000) и
кабинет (:3001), наполнит демо-магазином «Продукты на Абая» (28 товаров,
торговый день с чеками, долгами, бонусами и возвратом) и напечатает
логин/пароль владельца. Повторный запуск безопасен.

## Что нужно поставить (один раз)

1. **PostgreSQL 16** — https://www.postgresql.org/download/windows/
   При установке запомни пароль пользователя `postgres`.
2. **Node.js 22 LTS** — https://nodejs.org

Проверь в PowerShell:
```powershell
node -v      # должно быть v22.x
psql --version
```
Если `psql` не найден — добавь в PATH: `C:\Program Files\PostgreSQL\16\bin`

## Запуск (5 минут)

### Шаг 1. Создать базу

```powershell
cd "C:\Users\magzh\Desktop\Magzhan Проекты\Shop\1. Магазин\shop"
$env:PGPASSWORD="ТВОЙ_ПАРОЛЬ_ОТ_POSTGRES"
psql -U postgres -f db\setup.sql
```

Это создаст: базу `shop_dev`, роль `shop` (для миграций) и роль `shop_app`
(для работы программы — под ней действует изоляция аккаунтов).

### Шаг 2. Накатить миграции

```powershell
psql -U postgres -d shop_dev -f db\migrate.sql
```

Проверка — должно быть 88 таблиц:
```powershell
psql -U postgres -d shop_dev -c "SELECT count(*) FROM information_schema.tables WHERE table_schema='public'"
```

### Шаг 3. Собрать сервер

```powershell
cd server
npm install
npx tsc
```

### Шаг 4. Прогнать все тесты

```powershell
.\run_all.ps1
```

Ожидаемый результат:
```
ИТОГО: пройдено 1553, провалено 0
```

### Шаг 5. Запустить сервер

```powershell
node dist\main.js
```
Сервер поднимется на `http://localhost:3000`.

## Если что-то не так

**«Connection refused»** — служба PostgreSQL не запущена:
```powershell
Get-Service postgresql*
Start-Service postgresql-x64-16
```

**«password authentication failed for user shop_app»** — пароль роли не совпал.
Пересоздай роль:
```powershell
psql -U postgres -c "ALTER ROLE shop_app WITH PASSWORD 'change_me_in_prod'"
```

**Тест падает на первом запуске, а на втором проходит** — так бывает, если база
ещё просыпается. Запусти `.\run_all.ps1` второй раз.

**Кириллица в консоли квадратиками:**
```powershell
chcp 65001
```

## Как читать тесты

Каждый тест — это сценарий живого магазина, а не проверка функции. Например
`test/pos.e2e.js` открывает смену, пробивает чеки, делает возврат, закрывает
смену с недостачей и сверяет деньги.

Тесты запускаются на **настоящей базе** и создают себе аккаунт при каждом
прогоне — они не мешают друг другу и не требуют чистки.

Запустить один тест:
```powershell
$env:PGUSER="shop_app"; $env:PGPASSWORD="change_me_in_prod"; $env:PGDATABASE="shop_dev"
node test\pos.e2e.js
```

## Что готово и что нет

**Готово и проверено на живой базе:** операторская админка (метрики SaaS, ручные Kaspi-продления с прозрачными платежами, заморозка — всё через SECURITY DEFINER без ослабления RLS), двуязычный лендинг (RU/ҚАЗ) с честным сравнением цен и заявками на пилот (honeypot + лимит по IP + операторский ключ), приёмочный тест «День магазина» (полный цикл владельца до тенге — ворота релиза), консультанты с процентом и отчётом «к выплате», чек с бонусами и долгом покупателя, покупатель на кассе (долг с лимитом и подтверждением старшего, бонусы по правилам кабинета, погашение долга у кассы, всё офлайн), Docker-деплой с трекингом миграций и суточными бэкапами, касса Flutter (офлайн-продажи, смены с X/Z, возвраты, отложенные чеки, ESC/POS-печать; контракт закреплён сквозным тестом), снимок каталога и дельты для устройств, HTTP-API кабинета (90+ эндпоинтов), кабинет владельца (12 страниц), сотрудники и роли, автотриал при регистрации, товары, склад со средневзвешенной
себестоимостью, касса с офлайном, фискализация (интерфейс), контрагенты и
долги, финансы, отчёты и дашборд, документы Казахстана, лояльность,
оборудование, переезд с UMAG, ИИ-функции, биллинг.

**Требует человека, не кода:**
1. Договор с WebKassa/ReKassa + боевые ключи + регистрация ККМ в КГД
2. Юрист: оферта и политика персональных данных РК
3. ЭЦП НУЦ РК + доступ к ИС ЭСФ; пороги ТИС у бухгалтера
4. SMS-шлюз, ключ ИИ-провайдера, договор эквайринга Kaspi
5. Подписка UMAG (8 800 ₸) — снять реальные выгрузки для импортёра
6. Весы Rongta и принтер Xprinter на пилот

Везде, где нужен внешний доступ, в коде стоит честный интерфейс с симулятором
для проверки логики — выдуманных контрактов нет.
