# Табыс — как начать работу с репозиторием

Система учёта для розничных магазинов Казахстана. Работает у клиента.

## Быстрая проверка, что всё на месте

```
node scripts/check-invariants.js     # 90 правил, должно быть «всё на месте»
```

Это сторожа: каждое правило — пережитая поломка. Если что-то нарушено,
вывод скажет что именно и **зачем** это правило существует.

## Сборка кабинета

```
cd admin && npm install && npx next build
```

Должен появиться `.next/prerender-manifest.json` — без него кабинет не
поднимется на сервере.

## Ветки

- **main** — истина, сюда попадает вся работа
- **prod** — то, что стоит на сервере. Выкладывается только она.

Разделение спасает от «поправил на ходу и сразу уехало клиенту».

## Что где

```
server/       NestJS + чистый pg. Изоляция магазинов на уровне строк
admin/        Next.js 14, кабинет владельца. Все страницы клиентские
pos-desktop/  касса для Windows (Electron)
pos/          касса для Android (Flutter)
db/           49 миграций, применяются по порядку
deploy/       выкладка, проверки, восстановление
scripts/      сторожа
docs/         решения по частям — почему сделано именно так
```

## Три ловушки этого кода

1. **`localStorage` только внутри `useEffect`** — обращение при
   отрисовке роняет сборку, кабинет не поднимается.
2. **`Select` принимает `options={[{value,label}]}`**, а не вложенные
   элементы.
3. **Имя базы только `tabys-db`** — по общему имени `db` сервер уходил
   в базу соседнего проекта на том же сервере.

Все три закреплены сторожами.
